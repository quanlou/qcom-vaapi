Experimental ARM64 VA-API driver for **Snapdragon X Elite X1E80100**.

Download `qcom-vaapi_0.1.1.rc.5_arm64.deb` and install with:

```sh
sudo apt install ./qcom-vaapi_0.1.1.rc.5_arm64.deb
```

Restart video apps afterward. `vainfo` should report `qcom-vaapi 0.1.1-rc.5`
and `VAProfileAV1Profile0`.

- H.264 Baseline/Main/High, HEVC Main/Main10, VP9 Profile 0.
- Experimental **8-bit AV1**, including Chrome 4K playback and seeking.
- Stable surface backing, corrected decoder waits and lower CPU mapping usage.
- Includes the AV1 companion, license notices, corresponding FFmpeg sources,
  build inputs, qualification summary and SHA-256 checksums.

**Compatibility:** built on Ubuntu 26.10 development; needs ARM64, glibc 2.44,
libva 2.24 and a compatible patched Iris kernel. Tested on Dell XPS 13 9345
with `7.3.0-15-qcom-x1e` and reviewed Iris/QRTR fixes. Kernel modules and
firmware are not included. Older Ubuntu releases cannot use this binary unchanged.

The decode source passed 268 host tests, the strict codec/export matrix,
7/7 session churn cases, and exact pixels/order for 510 4K AV1 frames.
A local Chrome 4K test measured zero dropped frames over 55 seconds and
resumed after seeking. Live YouTube confirmed hardware decoding, with some
uneven frame timing. The published binary is the rc.5 label-only rebuild;
hardware results belong to the preceding binary with identical decode source.

10-bit AV1, film grain, Firefox, other chips and general suspend/resume behavior
remain unqualified. This is a hardware-specific prerelease.

See [release details](https://github.com/quanlou/qcom-vaapi/blob/main/docs/releases/0.1.1-rc.5.md)
for build instructions, tested module IDs and validation scope. The exact
shipped driver source is included separately from the tagged repository source.
