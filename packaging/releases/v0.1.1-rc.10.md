**RC10 development prerelease — hardware playback qualification is pending.**
For Linux on Snapdragon X Elite **X1E80100 / ARM64**.

RC10 combines:

- Direct zero-copy frame output for compatible H.264 / HEVC buffers.
- GPU frame transfers for supported NV12 / P010 layouts, avoiding CPU pixel copies.
- Experimental 8K limits, with separate surface and CAPTURE memory budgets.

GPU transfers still move pixels; unsupported layouts and CPU images can use CPU
copies. AV1 remains experimental: 8-bit, no film grain, and some ordinary FFmpeg
AV1 inputs fail before decode.

### Install

Download `qcom-vaapi_0.1.1.rc.10_arm64.deb` and `SHA256SUMS`, then:

```sh
sha256sum --check --ignore-missing SHA256SUMS
sudo apt install ./qcom-vaapi_0.1.1.rc.10_arm64.deb
```

Restart video apps. `vainfo` reports RC10, GPU frame transfers and experimental
8K. Requires glibc 2.44, libva 2.24 and compatible Iris kernel / firmware.
Built on Ubuntu 26.10 development with patched `7.3.0-15-qcom-x1e` modules.
This package installs userspace libraries; kernel / firmware setup is separate.

### Validation and limits

318 combined host tests, 316 normal tests, strict Clippy, 242 Python tests and
host stress checks passed. Captured 8K AV1 assembly passed for seven coded
frames. This exact `.deb` was installed locally and its files verified.

**The combined hardware codec matrix, buffer-reuse checks and 8K30 playback
have not passed.** VP9 session reuse produced Iris system faults on prior
candidates; the latest teardown fix is not yet hardware-tested. Sustained
4K60 / 8K30, 8K60, Firefox 8K and general suspend/resume remain unverified.

Assets include the unchanged AV1 companion, matching companion sources,
exact driver build source, tagged source, checksums and `qualification.json`.
The driver binary was built from `a30f4abff4147ae86445f25466e2cc50ed36b595`;
subsequent tag changes concern documentation and release packaging only.
