Experimental ARM64 VA-API driver for **Snapdragon X Elite X1E80100**.

RC6 fixes the export-handle growth that caused Firefox to hit `TooManyExports`
and fall back to software decoding. The driver now retains one private handle
per stable surface backing, preserving client descriptor lifetimes.

Download `qcom-vaapi_0.1.1.rc.6_arm64.deb` and `SHA256SUMS`, verify its hash, then:

```sh
sudo apt install ./qcom-vaapi_0.1.1.rc.6_arm64.deb
```

Restart video apps afterward. `vainfo` should report `qcom-vaapi 0.1.1-rc.6`.
Includes the AV1 companion, corresponding sources, licenses and qualification summary.

**Validation:** 270 host tests passed (4 ignored), formatting and strict Clippy,
required H.264 1/30/300-frame checks, HEVC/Main10/VP9, GL/export, resolution,
long playback, and 7/7 session churn cases. Regressions cover 1,024 repeated
exports/reuses for NV12 and P010 and client lifetime after surface destruction.

**Firefox and Chrome sustained playback on this build is still unqualified.**
The cache-path sandboxed Firefox attempt could not load the driver. Canonical
installation/browser checks did not run because administrator authentication
did not complete. The exact RC6 4K AV1 replay did not run because the decoder
was busy at preflight. Historical RC5 browser results do not qualify this binary.

**Compatibility:** ARM64, glibc 2.44, libva 2.24 and a compatible patched Iris
kernel; built on Ubuntu 26.10 development for the tested Dell XPS 13 9345.
Kernel modules and firmware are not included. Experimental 8-bit AV1 only;
10-bit AV1, film grain, other chips and general suspend/resume remain unqualified.

include hashes, the tested kernel/module identities and validation scope.
