Repeated-export peer review correction (host-only)
The normal export_ready_surface callsite guards stabilization by checking that
reserved_capture_for(surface)==surface.cap_idx. Normal repeated ready exports
therefore skip copying. A mismatched index, however, could enter stabilization
and idempotent reserve_capture would return already exported sameowner backing.
An attempted copy could overwrite that allocation, and failed bounds/cache
access could release its earlier reservation. Do not rely only on callsite
invariants to prevent this ownership loss.

stabilize_published_capture now checks for existing ownership before any copy:
matching index returns read-only/idempotently; mismatched index fails without
modifying the earlier allocation. Only a newly acquired reservation is ever
subject to failed-copy cleanup.

New repeated_stabilization_never_refreshes_or_releases_an_existing_export
regression fails before the guard, passes afterward. It verifies outstanding
export_refs2, reservation identity, bytesused and every mapped byte remain
unchanged for conflicting valid snapshot, matching repeated export and an
oversized snapshot that would otherwise undo the earlier reservation.
