Authoritative metadata investigation
The official libva AV1 picture structure has no refresh_frame_flags. Its
ref_frame_map describes references available to the current picture, not the
post-decode refresh decisions. Different refresh decisions can therefore have
the same VA picture parameters and tile bytes. Observing the next reference map
can detect divergence, but cannot provide authoritative decisions before the
current synchronous submission. The diagnostic shadow-map guard remains useful;
it does not establish a complete reconstruction contract.

Additional sequence syntax not represented by this VA structure includes actual
sequence maximum dimensions, frame-ID syntax, sequence screen-content/integer-MV
selection, enable_warped_motion, enable_ref_frame_mvs, enable_restoration,
separate_uv_delta_q, timing/decoder-model/operating-point data, and complete color
primaries/transfer metadata. Current defaults and picture-derived values cannot
establish a faithful, stable sequence for arbitrary streams. Per-frame frame-size
inheritance/override and render-size choices are also not preserved completely.

https://raw.githubusercontent.com/intel/libva/master/va/va_dec_av1.h
  VADecPictureParameterBufferAV1; VASliceParameterBufferAV1. The tile contract
  supplies per-tile offsets, lengths, and coordinates, not original frame headers.
https://raw.githubusercontent.com/FFmpeg/FFmpeg/master/libavcodec/vaapi_av1.c
  vaapi_av1_start_frame maps parsed state into the limited VA structure;
  vaapi_av1_decode_slice sends parsed tile bytes with per-tile parameters.
