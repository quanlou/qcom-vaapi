# 0.1.1-rc.8 development snapshot

RC8 retains RC7's direct DMA-BUF decode path and adds per-phase EndPicture
timing logs when `V4L2_VA_DEBUG` is enabled. It does not establish a new buffer
ownership fix or qualified sustained 4K60 playback.

The ARM64 development package contains the Rust VA-API library and unchanged
experimental AV1 companion. It also includes the kernel patch sources, their
GPL license and an optional GPU power helper. Installation neither replaces
the Iris kernel module nor enables the helper service.

On X1E80100, the optional `qcom-vaapi-playback-power.service` raises the GPU
minimum to 550 MHz while Iris is referenced and runtime-active, restoring the
prior minimum when inactive or stopped. It can increase power use and is
disabled by default. Its first installation needs a systemd daemon reload
before manual activation. This policy has only short diagnostic playback
evidence, not broad power-management qualification.

Kernel patches 0007 and 0008 remain experimental. A short clock trial approached
60fps, but warm decoder reopen still failed, and a later lifetime-candidate
trial recorded kernel memory corruption. Clean user-run buffer ownership
traces used the original EL2 module, not these candidates, and do not resolve
those failures. Firmware submission/response addresses matched the attached
buffers even during repeated object changes at the same DMA address; physical
write correctness and retired-buffer isolation remain unverified.

This snapshot may be installed locally for continued development. A tagged
release and hardware qualification remain pending. The full evidence scope is
recorded in the [ownership checkpoint](../4k60-ownership-status-20261004.md).

Before local installation: 291 Rust tests passed (4 fixture-dependent tests
ignored), 233 Python tests passed, formatting and strict all-target/all-feature
Clippy passed, and the system-AV1 release library built successfully. The two
isolated kernel C models also passed their scoped candidate checks. These are
host checks and do not establish new hardware playback qualification.
