# 0.1.1-rc.7 development build

H.264, HEVC and VP9 can decode directly into the surface DMA-BUF exported to
Chrome or Firefox when Iris supports decode-order output. The driver selects
one CAPTURE target at a time and retains completed pixels in the surface's
own allocation. VP9 hidden-reference handling, completion ownership, context
replacement and browser synchronization are covered by the new checks.

The measured Chrome GPU process used about 10% of one core, compared with
47% for the prior copy candidate. Chrome's 4K VP9 playback/seek check and a
retimed Firefox 4K30 check pass. **Firefox 4K60 still drops frames and remains
unqualified; sustained 60 fps is not established for Chrome either.**

See [the full validation report](../../direct-buffer-validation-20261003.md)
for exact binary hashes, hardware, checks and limitations. The unchanged AV1
companion is included in the system-av1 package; AV1 retains its copy path.

This is a development package built from the repository commit recorded in
its copyright notice and qualification receipt. No RC7 GitHub release is
published by creating or installing this package. Restart video applications
to load the updated library. `vainfo` reports `qcom-vaapi 0.1.1-rc.7`.
