# 0.1.1-rc.5

Experimental VA-API decoding for Qualcomm Iris on Snapdragon X Elite X1E80100.
This release includes an ARM64 Debian package with 8-bit AV1 support.

## Install

Download `qcom-vaapi_0.1.1~rc.5_arm64.deb` and `SHA256SUMS` from
[GitHub Releases](https://github.com/quanlou/qcom-vaapi/releases/tag/v0.1.1-rc.5).
Check its hash against `SHA256SUMS`, then install:

```sh
sudo apt install ./qcom-vaapi_0.1.1~rc.5_arm64.deb
```

The package installs `msm_drv_video.so` and `libiris_av1_complete.so` under
`/usr/lib/aarch64-linux-gnu/`. Restart video apps to load them.
`vainfo` should report `qcom-vaapi 0.1.1-rc.5` and AV1 Profile 0.
Remove it with `sudo apt remove qcom-vaapi`.

## Compatibility

- ARM64, Snapdragon X Elite X1E80100; tested on Dell XPS 13 9345.
- Built on Ubuntu 26.10 development; requires glibc 2.44 and libva 2.24 or newer.
- Tested kernel: `7.3.0-15-qcom-x1e`, with reviewed Iris and QRTR fixes.
- Kernel modules and firmware are **not included**. A matching release string
  alone does not establish compatible kernel behavior. Review the
  [kernel fixes](../../kernel/README.md) and qualify your kernel before relying
  on this driver.
- AV1 supports 8-bit Profile 0 without film grain. 10-bit AV1 and Firefox are
  unqualified. Other hardware and general suspend/resume reliability are untested.

## Changes

- Accept Chrome's original AV1 buffers, including multiple coded frames.
- Preserve VA surface storage across decoder reuse and PRIME export.
- Wait for elapsed decoder deadlines and avoid premature drain commands.
- Size capture queues from firmware requirements and map buffers only when used.
- Align the embedded driver label with the rc.5 package version.

## Validation

The decode source passed 268 host tests, the required H.264 1/30/300 frame
matrix, HEVC/Main10/VP9 parity, GL/export checks, resolution and long-playback
checks, and all 7 session churn cases. A traced 4K AV1 replay matched all 510
coded frames in pixel content and order, with clean teardown and kernel logs.
Its complete monitored process tree peaked at 521,016 KiB (509 MiB).

A local Chrome 4K AV1 test ran for 55 seconds, displayed 1,329 frames with
1,433 hardware completions, resumed after seeking, and measured zero dropped
frames. A separate live YouTube capture confirmed `VaapiVideoDecoder` at
3840×2160, with successful seeking and no recorded decode fallback. Some
frame timing unevenness remains; the local zero-drop result does not apply to
every YouTube stream.

## Build the AV1 companion

The release includes `ffmpeg-companion-source.tar.xz` (corresponding FFmpeg
source) and `ffmpeg-companion-build-inputs.tar.xz` (configuration and ARM64
static libraries used for the shipped helper). The driver source archive
contains the companion source and headers under `producers/`.

On an ARM64 build host with a C toolchain, libva development headers, X11
headers, zlib development headers and pkg-config, unpack the FFmpeg source
archive and build position-independent static libraries:

```sh
mkdir ffmpeg-build
cd ffmpeg-build
../ffmpeg-source/configure --disable-everything --disable-doc --disable-debug \
  --disable-network --enable-pic --enable-decoder=av1 --enable-hwaccel=av1_vaapi \
  --enable-vaapi --enable-parser=av1
make -j"$(nproc)" libavcodec/libavcodec.a libavutil/libavutil.a
cd ..
cc -shared -fPIC -O2 -fvisibility=hidden -Wl,--exclude-libs,ALL \
  -Iffmpeg-build -Iffmpeg-source -I/path/to/qcom-vaapi/producers \
  /path/to/qcom-vaapi/producers/av1-cbs-complete-library.c \
  ffmpeg-build/libavcodec/libavcodec.a ffmpeg-build/libavutil/libavutil.a \
  $(pkg-config --libs libva libva-drm libva-x11 x11 zlib) -lm -lpthread \
  -o libiris_av1_complete.so
```

This is a source-build recipe, not a guarantee of byte-identical output or
hardware qualification on another host. To use the shipped configuration,
consult `ffmpeg-build/ffbuild/config.mak` in the build-input archive.

Keep FFmpeg's license notices and corresponding source available when
redistributing the companion. The `.deb` includes license files under
`/usr/share/doc/qcom-vaapi/`; the Rust driver remains MIT-licensed.
