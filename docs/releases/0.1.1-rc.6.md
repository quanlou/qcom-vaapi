# 0.1.1-rc.6

Experimental ARM64 VA-API driver for Qualcomm Iris on Snapdragon X Elite X1E80100.

## Fix

Firefox exports a decoded surface repeatedly. Earlier builds retained a new
private file descriptor for each export until surface destruction. After 64
exports of one surface, the driver returned `TooManyExports` and Firefox fell
back to software decoding.

RC6 retains one internal handle per stable surface backing. Each client still
receives its own descriptor; client handles remain valid after the VA surface
is destroyed. Reusing a surface can update its contents, as allowed by VA-API.
The fix preserves allocation limits and does not raise the old export limit.

## Install

Download `qcom-vaapi_0.1.1.rc.6_arm64.deb` and `SHA256SUMS` from
[the release](https://github.com/quanlou/qcom-vaapi/releases/tag/v0.1.1-rc.6).
Verify the checksum, then install:

```sh
sudo apt install ./qcom-vaapi_0.1.1.rc.6_arm64.deb
```

Restart video apps to load the new libraries. `vainfo` should report
`qcom-vaapi 0.1.1-rc.6`. The package includes `msm_drv_video.so`, the unchanged
AV1 companion `libiris_av1_complete.so`, and their license notices.

## Compatibility

- ARM64, Snapdragon X Elite X1E80100; tested host: Dell XPS 13 9345.
- Built with Rust 1.92.0 on Ubuntu 26.10 development; requires glibc 2.44 and
  libva 2.24 or newer.
- H.264 Baseline/Main/High, HEVC Main/Main10, VP9 Profile 0, and experimental
  8-bit AV1 Profile 0 without film grain.
- Tested kernel: `7.3.0-15-qcom-x1e` with the reviewed Iris/QRTR fixes described
  in [the kernel documentation](../../kernel/README.md). Kernel modules and
  firmware are not included.
- Tested module build IDs: Iris `231cb9f3a0141c3ddfa7b8df87df0889eff2f5f2`,
  QRTR `a3742ff58316450e2f4cbc77f799d29f567277d4`, QRTR MHI
  `2a9b093bf2b5cfcddd4a3b31f5b3ad8cb3757de4`.

## Validation

The exact RC6 driver passed 270 host tests (4 ignored), formatting, strict
Clippy, the required H.264 1/30/300-frame parity matrix, HEVC/Main10/VP9 checks,
GL/export checks, resolution changes, long playback and all 7 session churn
cases. Decoder sessions exited cleanly and kernel logs were clean.

Two regressions fail on the previous implementation and pass with this fix.
They cover 1,024 decode/reuse/export cycles for NV12 and P010, a constant single
internal handle, storage reuse without another allocation or private duplicate,
and client access after driver surface destruction.

**Sustained Firefox and Chrome playback on RC6 remains unqualified.** The first
sandboxed Firefox attempt could not load the candidate from its cache location;
no RC6 hardware frames were decoded in that attempt. Canonical installation
and the subsequent browser checks did not run because administrator
authentication did not complete. The new exact 4K AV1 replay also did not run:
its read-only preflight found the decoder busy. These are not passing checks.
Earlier RC5 4K/browser results are historical and do not qualify this binary.
10-bit AV1, other chips and general suspend/resume behavior remain unqualified.
